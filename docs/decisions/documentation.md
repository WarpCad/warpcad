# Documentation: where the docs live, and the published Help contract

**Status:** accepted 2026-10-31, from `TODO/M20-docs-028-docs-home-and-published-help-contract.md`. The owner asked
on 2026-10-26 whether the docs belong here or in the home-page or native repositories. This record answers that.

## Decision

**The source stays in `warpcad/docs/`.** The docs are published as a versioned contract, `help/index.json`
with `help/<slug>.html` and `help/img/…`. Consumers read the published files, never the Markdown.

| Consumer | What it reads | When |
|---|---|---|
| The web app's Help sheet | `help/index.json`, `help/<slug>.html`, `help/img/…`, same origin, precached | every build of this repository |
| The home page (`warpcad.github.io`) | `https://app.warpcad.com/help/index.json` and `app-overview.png` | its daily rebuild |
| The native apps (M19) | the same `help/` folder inside `dist-native/`, bundled by `build:native` | each native build |

Moving the source to another repository breaks three things this one relies on:

- Every docs picture is generated by driving this repository's UI (`e2e/docs/*.docs.js`, `npm run docs:media`,
  guarded by `e2e/docs-media.spec.js`). The pages and the specs that make their pictures must change together.
- CLAUDE.md's per-task Documentation gate puts a control and its docs page in the same task and commit.
- The in-app Help is built from `docs/` by this repository's Vite build (`scripts/vite-plugin-help.mjs`).

## The published contract

- **`help/index.json`** says which build produced it: `schema` (now `1`), `version` and `commit` (the same
  `APP_VERSION` and `APP_COMMIT` that stamp `<meta name="version">`). Its `order`, `pages` and `headings` keep their
  shape. It adds `aliases`, from the lockfile below.
- **`docs/help-slugs.json`** lists every page slug and `TOPICS` id that has ever been published, and maps each
  retired slug to the page that replaced it (`aliases`). The build fails when a published slug is missing from the
  list, when a listed slug is gone without an alias, when an alias points at a missing page or at another alias, or
  when an alias shadows a live page. Add slugs with `npm run help:slugs`. Removing one is an alias, added by hand.
- **An alias opens the replacement.** `HelpSheet.vue` resolves the slug through `resolveSlug`, and the hash follows
  the page it opened. A slug that is neither a page, a topic, nor an alias gets `testing-012`'s moved line.

## Who writes which docs

- **End-user docs**, for every platform, go in `warpcad/docs/` only. That includes native-only pages and sections.
  A TODO filed in `warpcad-native` that changes what a user sees edits `../warpcad/docs/` and carries a
  `> Two repositories` banner. Its docs change passes this repository's gates (`npm run spdx`, the help build's link
  check, `e2e/docs-media.spec.js`).
- **Developer docs** live next to the code they describe: `warpcad-native/README.md` (how to build the shell),
  `warpcad.github.io/README.md` (how the home page builds), and this repository's `CONTRIBUTING.md` and `docs/decisions/`.
- **The home page's own copy** (hero, What it does) is page copy in `warpcad.github.io`, not docs. It links to docs
  pages and never restates them.

## How the native apps include Help

This record does not choose. That choice belongs to `build-020` (ship the GIFs or not, and which prose licence
option applies under `docs/decisions/app-store-licensing.md`). The contract supports three shapes, so whichever
answer the owner gives is a configuration change in `build:native`:

| Shape | Bundle size | Offline | Licence fit | Cost |
|---|---|---|---|---|
| **Bundled** (today's `dist-native/`) | +184 MB of GIFs (light 85 MB + dark 99 MB; was +89 MB before `docs-030`) | Full | Needs (a) | None. It is what `build:native` does now |
| **Bundled text and stills, GIFs from the web** | about +40 MB (stills 42 MB, light 21 MB + dark 21 MB, plus text; was about +19 MB) | Text and stills | Needs (a) | `helpRuntimeCaching()`'s GIF pattern points at `app.warpcad.com`, and the shell's CSP allows that one `img-src` |
| **All Help from the web** | +0 | None until visited | Fits (b) | `helpUrl()` gains a build-time base (`VITE_HELP_BASE`), and the shell's CSP allows `connect-src` and `img-src` for `app.warpcad.com`. Must show version skew, which the `version` and `commit` fields make visible |

### Light and dark pictures (`docs-030`, 2026-11-03)

Every docs picture is recorded twice from one spec, in `prefers-color-scheme: light` (`x.png`, `x.gif`) and `dark`
(`x.dark.png`, `x.dark.gif`), through the `docs-<size>` and `docs-<size>-dark` Playwright projects. The help build wraps a
pair in a `<picture>` whose dark `<source>` is keyed to `prefers-color-scheme`; a reader downloads one variant, so the web
cost is unchanged. What grew is the repository and the Pages artifact: `docs/media/` 87 MB to 184 MB (75 dark GIFs, 99 MB),
`docs/screenshots/` 24 MB to 42 MB (160 dark stills, 21 MB). The service worker does not precache the dark stills
(`HELP_PRECACHE_IGNORES`; they are runtime-cached with the GIFs), so the install size is unchanged.

**OPEN: the native shape is undecided and needs the owner's call.** The table above is repriced with these numbers and
nothing else changed. The native apps would ship both variants (the OS theme picks, as on the web), so "Bundled" is now
about +184 MB of GIFs, which is the strongest argument yet for one of the two web-sourced shapes. This record does not
choose; it belongs to `build-020` step 1.

## Rejection table

| Option | Why not |
|---|---|
| Move `docs/` into `warpcad.github.io` (M20) | The app would depend on its own marketing site. Every UI task would need a commit in two repositories, and the docs-media specs would run in a different repository from the pages they illustrate |
| Move `docs/` into `warpcad-native` (M19) | Same problems, and the native-only pages are a handful of the 31. The native apps run this repository's UI, so their pages describe this repository's code |
| A separate `warpcad-docs` repository, consumed as a submodule or npm package | Three repositories in step instead of one. A version pin to bump on every UI change, and the media generator still needs the app, so it would stay here anyway |
| A second rendering on `warpcad.com/docs/` | Already rejected in `docs-026` question 4: two renderings to keep in step, and a second copy of about 70 MB of GIFs |
| **Keep the source here; publish `help/` as a versioned contract** (chosen) | One source, one renderer, one media pipeline. Consumers depend on a published URL and a schema, not on a file layout |

## Revisit when

- **Search traffic matters** (`docs-026` question 4's trigger). The cheap path stays in this repository: have the
  help build also emit a crawlable page per slug (`app.warpcad.com/help/<slug>/`, the same fragment in a minimal
  shell with an **Open in WarpCad** link and a canonical URL). That keeps one renderer. A second site does not.
- **A native shape is chosen** (`build-020` step 1; the dark twins doubled the bundled cost, see above). Its version-skew line is the follow-up for the
  "All Help from the web" shape.
