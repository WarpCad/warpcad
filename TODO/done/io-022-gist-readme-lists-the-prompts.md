> **What shipped (2026-10-28).** As proposed, with these differences. The README section is built in `gistReadme.js` from prompts the composable resolves to body names (`produced` ids that are not bodies are not named). Mentions are broken as `&#64;` in prompt text and in the names a prompt produced, which the proposed fix did not spell out. The sheet shows the checkbox only with at least one prompt. **Not done:** the Step 6 hand-drive of acceptance scenario 30 is still to be run; the checkbox docs shot is `docs/screenshots/gist-prompts.png` (generated by `e2e/docs/share-gist.docs.js`).

## Goal

**In user terms:** the owner's fan-duct gist shows a README with three body names and a link, but nothing
about how the part came to be. When the project has stored prompts (`ai-031`), the README gains a **How this
was made** section listing them, so a reader on github.com sees the requests without opening WarpCad.

This reverses a line in `src/core/gistReadme.js`: its header says intent text and the AI conversation are
**deliberately not** in the README, because it is "the part that gets skimmed and indexed". The owner has now
decided prompts belong there, so the reversal is on purpose. The safeguards the file already has stay: every
prompt is data, never markup and never instructions.

## Interaction model

- **Precondition**: a project with at least one stored prompt; a gist publish or update.
- **Trigger**: the existing **Publish** / **Update gist** (and **Save as gist…**, `io-021`). A **Include
  prompts in the README** checkbox in the Share sheet's gist group, **on by default**, lets the owner leave
  them out. It states plainly that a **public** gist is listed on GitHub for anyone to read.
- **Feedback**: the published README shows the section; the sheet's note under the checkbox names how many
  prompts will be sent.
- **Placement / Selection response / Selection count**: n/a.
- **Small-screen behavior**: one checkbox row in the existing sheet at 390 px.

## Proposed fix

Render each prompt as a block quote after `escapeMarkdownText` and the cleaning the README already applies,
newest last, each followed by the names of the bodies it produced (`produced`, `ai-031`). Cap the section
(for example 20 prompts and 6,000 characters in all, then "and N more"), the way bodies are capped by
`MAX_LISTED_BODIES`. The README stays under GitHub's rendering limits. Nothing else changes: still no
standing instructions or chat transcript. An empty prompt list omits the section; an unticked box omits it.
The `.ndjson` carries the prompts either way, so say so in the checkbox note: unticking hides them from the
README, not from the file.
