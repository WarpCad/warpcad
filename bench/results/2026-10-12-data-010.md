# `TODO/data-010`: what replica metadata and `mergeFrom` cost

**Machine**: Apple M4 Pro, macOS 27.0, Node v24.14.1. Plain Node (V8), no browser — `core` is
framework-free, so this is the document layer itself.
**Fixtures**: `data-004`'s 50-body fillet scene (200 records) and `perf-001`'s 24-body scene
(12 Pi boards + 12 bolts, 48 records).
**Method**: `node bench/merge-benchmark.mjs --runs 21`. Fresh documents per run, median of 21.
Baseline: the same script in a worktree of the commit before this task.

## Per-mutation stamping

| mutation | scene | before | after |
|---|---|---|---|
| `append` one cuboid | 200 records | 0.057 ms | 0.130 ms |
| `append` one cuboid | 48 records | 0.042 ms | 0.069 ms |
| `setSuppressed` (last row) | 200 records | 0.852 ms | 0.877 ms |
| `setSuppressed` (last row) | 48 records | 0.166 ms | 0.184 ms |

The stamp is a before/after diff of the transaction, O(records), about +0.03–0.07 ms. It is
dwarfed by the fold the same mutation already pays (`core-031`'s numbers are in milliseconds),
so it is not visible there.

## `mergeFrom` (other side appended a body and suppressed a row)

| scene | default fold cache | `foldCache: null` |
|---|---|---|
| 200 records | **1.24 ms** (p95 2.0) | 71.5 ms (p95 77.9) |
| 48 records, 24 bodies | **0.28 ms** (p95 3.0) | 373.9 ms (p95 610) |

With the cache a merge rebuilds only the rows that arrived (`foldReuse.spec.js` asserts it).
The uncached column is the cold-fold cost of the same document — what Open pays — and is the
worst case, not the merge path.
