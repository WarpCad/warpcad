# `TODO/core-085`: a whole-model Subtract of a dense 3MF, before and after transferring the operands

**Machine**: Apple M4 Pro, macOS 27.2.1, Node v24. **Browser**: Chromium, 1440x900, production build.
**File**: two copies of the owner's `5036 RGB Matrix 2.5mm/5036 RGB Matrix.3mf` (1.9 MB, 25 parts, 219,540
triangles each; never committed), imported through **File ▾ → Import model…**, placed side by side, the first picked
in the Objects list and the second ticked, then **Subtract**. These figures were taken by the Opus half of the task
and are recorded here with their provenance (3 runs per cell for the headless "after" and for `--headed`, 1 run for
the "before" cells, which match the 2026-11-17 drive in VERIFY.md `core-079` #2).

**Commands** (a build is served first):

```
npm run build && npx vite preview --port 4173 &
node bench/evaluation-mainthread.mjs --only whole-model-cut --mesh "<file>" --rates 1 --runs 3            # headless, software rasteriser
node bench/evaluation-mainthread.mjs --only whole-model-cut --mesh "<file>" --rates 1 --runs 3 --headed   # the Mac's GPU
```

| Moment | Before, headless | After, headless | Before, GPU (`--headed`) | After, GPU | Target |
|---|---|---|---|---|---|
| Longest timer gap at the click | 210 ms | median 20 ms (worst 24) | 208 ms (worst 224) | median 14 ms (worst 17) | 16 ms |
| Long Tasks at the click | 208 ms | none | 205, 222 ms | none | none |
| Longest timer gap at the landing | 244 ms | median 137-147 ms (worst 166) | 119 ms (worst 127) | median 47 ms (worst 48) | 50 ms |
| Long Tasks at the landing | 118, 124 ms | 97-122 ms | 110, 117 ms | none | none |

Idle floors (the browser's own cadence with nothing of the cut's to do): headless frames every 18-19 ms, GPU
every 9-10 ms.

**Reading it.**

- **The click meets its target on the GPU** (median 14 ms against 16) and drops no frame headless (the 20 ms median
  sits on the 18-19 ms headless frame floor). Cause, from CPU profiles: 195 ms of the 210 was `postMessage`
  structured-cloning the operands as nested JS arrays. Solids now cross as `{counts: Uint32Array, positions:
  Float64Array}` and planes as `Float64Array`, so they are transferred, and the packing runs in 4 ms slices that
  yield through `afterNextPaint`.
- **The landing meets 50 ms on the GPU only.** Headless it stays over (137-147 ms). Profile of the landing: 79 ms
  was the first read of `event.data`, now a transfer; about 30 ms is the app's own work (fold, mesh, normals,
  bounding sphere); about 110 ms is native frame time, a software rasteriser drawing the 220 k-triangle
  **non-indexed** result (660 k vertices, about 80 ms a frame). **The headless landing target is not met.**
  Follow-up `render-009`.
- One of eight headless sliced runs had a 1,022 ms full GC right after the pack (a 48 MB new ArrayBuffer at a
  400 MB heap). Follow-up `core-086`.

**The e2e** (`e2e/import-3mf.e2e.js`, "a dense 3MF as the whole-model cutter") uses a generated 25-part,
217,800-triangle 3MF and a Cube target, so the result is small: it asserts under 50 ms at the click and under 80 ms
at the landing (a rasteriser's one frame). Measured after the fix on the three laptop projects: click 0, 8 and
13 ms, landing 65, 47 and 27 ms (Chromium, Firefox, WebKit). Before the fix the click was 95-137 ms on Chromium.
`bench/whole-model-cut.mjs` keeps the two-copy case, the one with the large result.

**Phone width (VERIFY.md `core-079` #1, re-driven 2026-11-19)**: two generated dense models ticked at laptop width,
the viewport resized to 390x844, **Subtract** pressed, the DOM sampled every 30 ms for 30 s: the line *Subtract in
progress…* appears 91 ms after the click (it now shows while the operands are packed), sits at x 13, y 240 (172 x 29
px) inside the Operations panel, every button stays on screen, `scrollWidth` 390 = `clientWidth` 390 throughout.
