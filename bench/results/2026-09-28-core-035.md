# core-035 — design resolution and export resolution: measurements

Machine: Apple M4 Pro (`sysctl machdep.cpu.brand_string`), Node v24.14.1,
plain Node (no browser, no GPU — every number here is CPU-bound kernel work).
Script: `node bench/resolution-benchmark.mjs --runs 10`. "Before" is the same script run
against `git archive HEAD` (commit 2233c53) extracted to a scratch directory with this
checkout's `node_modules`, on the same machine, minutes apart. Times in ms.

## Reading it

- **No regression on the existing path.** A design-resolution export is the same work
  and the same bytes (12 360 / 960 triangles on both) — within run-to-run noise.
- **The fold-cache key change is free.** The policy is one identity comparison; the
  cached re-fold is 0.2 ms median before and after.
- **A Print export costs ~2.6× the design export on the 24-body scene** (171.9 vs 67.3 ms
  median) and runs entirely in the export worker, so none of it is on the main thread;
  `cancelExport()` terminates the worker if the user closes the popover mid-job.
- **Normal is cheaper than Legacy on real parts** (10 296 vs 12 360 triangles): the Pi
  board's many small holes drop from a fixed 32 sides to Normal's 16-20 floor, while
  large circles gain sides. That is the chord-tolerance design doing what it says.
- **Changing the design resolution to Print re-folds on the main thread** (76 ms median
  on 24 bodies), like Open and every other row action — it is a deliberate one-off, not
  a per-frame cost, and `core-032` owns moving cold folds off the main thread. The
  export override is the path for "preview coarse, print fine".
