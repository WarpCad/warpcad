# `TODO/core-031`: a re-fold that reuses unchanged records, before and after

**Machine**: Apple M4 Pro, 14 cores, 24 GB, macOS 27.0, Node v24.14.1.
**Browser**: Playwright 1.63.0, Chromium, **headless, software rasteriser**.
**Build**: browser rows run the **production build**, as `.claude/prompts/perf-benchmark.md`
rule 2 requires. "Before" is the tree at `65b86de` (HEAD before this task), built from a
git worktree and served with `vite preview --port 4174`. "After" is this task's tree on
`--port 4173`. Both runs use this task's extended `bench/evaluation-mainthread.mjs`. Node
"before" is this task's extended `bench/fold-benchmark.mjs` run against the unchanged
`src/` before any fix landed, so both columns come from the same script.
**Fixtures**: `fillet-50` is `data-004`'s 200-record scene. `24-bodies` is `perf-001`'s
12 Pi boards plus 12 bolts. `chain-40` (new) is one 400×40×10 plate with 40 cylinders
subtracted in turn: a **single lineage**, the worst case for reuse.
**Runs**: browser n=5 per cell, a fresh context per run. Node n=11 per cell. Medians.

```sh
node bench/fold-benchmark.mjs --runs 11
npm run build && npx vite preview --port 4173 &
node bench/evaluation-mainthread.mjs --url http://localhost:4173 --runs 5
```

## 1. Measured first: what option 1 would still cost

Option 1 (the fold as a worker job) has to hand back `scene.byId`, every record's value,
because a later synchronous `append` resolves operands against it. Pack +
structuredClone + unpack of the **whole** map, median (p95):

| scene | values | ms |
|---|---|---|
| fillet-50 | 200 | **10.3** (11.6) |
| 24-bodies | 48 | **18.9** (74.0) |
| chain-40 | 81 | **30.3** (33.3) |

That is main-thread cost on every row action, before any pending-state UI, with every
refusal made late. Section 2 shows the fold cache landing below that floor on every
row action measured, except the one case that is genuinely new work.

**An intermediate result that shaped the fix.** A cache of builds alone took the 24-body
row actions only from ~150 ms to ~125 ms. A CPU profile of a cached suppress showed
**0 builds** and ~95 ms in `evaluate → add → combine → booleans.union`: the scene group's
`add` re-unions every named composite on every fold. Keeping the `combine()`d part beside
the cached value is what took those rows to 0.1-6.5 ms.

**What is left.** Open, and chain-40's root edit, are new work. Open's records were never
built in this session. Every row after chain-40's root really does depend on it. These
are `TODO/core-032`.
